# 字段组显示条件（Location Rules）设计说明

## 1. 背景与目标

WEM Content Fields v1.0.0 当前通过字段组的 `post_types[]` 关联内容类型。该机制适合产品、文章等通用字段，但无法让字段组只显示在某一个 Page 的编辑界面。

本功能为字段组增加轻量级显示条件，首个使用场景是只在 About Us 页面显示企业介绍字段组。它不负责前台模板渲染，也不允许客户改变主题布局。

## 2. 范围

### 本次包含

- 字段组可选择「全部关联内容类型」或「仅在指定页面显示」。
- 指定页面支持选择一个或多个 WordPress Page。
- 新建与编辑字段组使用同一套配置和校验逻辑。
- Meta Box 显示、编辑资源加载和常规字段保存使用一致的页面匹配结果。
- JSON 导入/导出支持显示条件，并对旧版 Schema 做兼容迁移。
- 未匹配页面不会显示字段组，且不会通过常规 Meta Box 保存流程写入该组字段。
- 隐藏或修改显示条件不删除既有 Post Meta 数据。

### 本次不包含

- AND/OR 条件构建器。
- 按用户角色、模板、分类或字段值进行条件组合。
- Repeater / Gallery 等新字段类型。
- 前端页面构建器或模板修改。
- 自动创建页面或自动迁移页面内容。

## 3. 后台界面

扩展现有「新建字段组」和「编辑字段组」页面，不创建新的独立管理页面。

在「应用到内容类型」之后增加「显示条件」区域：

1. **全部关联内容类型**：默认值，保持 v1.0.0 既有行为。
2. **仅在指定页面显示**：显示 WordPress Page 多选器；至少选择一个页面后才可保存。

该页面选择器只列出可编辑的 Page，保存时由服务端重新验证页面 ID 与页面类型。页面标题只用于显示，不作为唯一身份标识。

## 4. 数据结构

字段组新增可选的 `location` 属性：

```json
{
  "location": {
    "mode": "all"
  }
}
```

指定页面的运行时配置：

```json
{
  "location": {
    "mode": "specific_pages",
    "page_ids": [123, 456]
  }
}
```

约定：

- 缺少 `location` 的旧字段组按 `mode: all` 处理。
- `mode` 仅允许 `all` 或 `specific_pages`。
- `specific_pages` 必须包含至少一个有效的 Page 标识。
- 页面 ID 在当前站点内作为准确匹配依据，不通过标题猜测目标页面。
- 显示条件只控制后台字段组的适用对象，不删除字段定义或字段值。

## 5. JSON 导入/导出与 Schema 兼容

由于旧版本插件会忽略未知字段，若继续把新增规则写入 Schema v1，旧版插件可能将受限字段组错误地导入为全局字段组。因此，新导出格式应升级为 Schema v2。

- 导出时，将本地页面 ID 转换为可迁移的页面引用信息（优先使用完整页面路径，并附带 slug/title 供预览和诊断）；不把源站 ID 当作目标站 ID 使用。
- 导入 Schema v1：自动补充 `location.mode = all`，保持旧文件行为。
- 导入 Schema v2：通过页面路径在目标站点解析 Page ID。
- 无法唯一解析的页面引用必须在预览中明确警告，不能静默扩大为「全部页面」。
- 导入后的未解析引用不得匹配其他页面；用户可在字段组编辑界面重新选择目标页面后保存。
- 导入仍遵循现有策略：不覆盖已有字段组；出现结构或标识冲突时整次导入失败。

具体 JSON 字段命名应在实现时与现有 Importer/Exporter 保持一致，并通过往返测试确认。

## 6. 匹配与保存行为

建议在 Definitions 中增加按当前对象筛选字段组的方法，例如 `for_object( $post_type, $post_id )`，统一处理：

- `add_meta_boxes`：只注册匹配当前对象的字段组。
- Meta Box 相关资源加载：仅根据匹配字段组判断是否需要媒体库或编辑器资源。
- `save_post`：仅保存当前对象匹配的字段组，并继续执行现有 Nonce、Capability、Autosave、Revision 和字段白名单校验。
- REST Meta：由于 `register_post_meta()` 是按 Post Type 注册，页面级规则不能只依靠隐藏 Meta Box 来实现。实现时需为受限字段增加按 `post_id` 判断的授权回调，确保受限字段不会因 REST 写入而绕过页面范围；不受限字段保持现有行为。

如果同一字段组通过 Runtime Definitions 注入，也必须经过同样的规范化与匹配规则；运行时定义不应被写回 Stored Definitions。

## 9. 设计原则

- 默认兼容，不改变现有字段组行为。
- 页面级条件属于字段组配置，不属于主题代码。
- 显示规则、字段定义和实际字段值彼此分离。
- 页面匹配失败时采取安全失败策略：不显示、不写入、不自动扩大范围。
- 页面布局仍由经典主题模板控制。
